# StockLight (종목신호등)

공공데이터(금융위원회 API)로 종목 하나를 **"실적 근거"와 "가격 위험"**으로 나눠 신호등 한 장으로 보여주는 데스크탑 리포트 앱입니다.

> **현재 상태: 1단계(API 호출 점검)만 완성.** 신호등 화면과 점수 계산은 아직 만들지 않았고, 지금 저장소에는 "공공데이터 API가 실제로 응답하는지, 종목명으로 5개 API를 이어서 받을 수 있는지" 확인하는 점검 스크립트와 규격 메모가 들어 있습니다.

## 1단계: API 첫 호출 점검

`collector/probe.mjs`가 종목 하나로 아래를 차례로 호출합니다.

| 순서 | API | 조회 키 | 가져오는 것 |
| --- | --- | --- | --- |
| 1 | KRX상장종목정보 | 종목명 | 법인등록번호(`crno`), ISIN코드(`isinCd`) — 다른 API를 잇는 연결표 |
| 2 | 기업기본정보 | `crno` | 회사명, 업종, 직원 수, 설립일 |
| 3 | 기업재무정보 | `crno` + 사업연도 | 매출·영업이익·순이익·자산·부채·자본·부채비율 (최근 3개 연도를 거꾸로 시도, 연결 재무제표 우선) |
| 4 | 주식시세정보 | `isinCd` | 최근 14일 시세 |
| 5 | 주식배당정보 | `crno` | 배당 내역 |

마지막에 "종목명 → 법인등록번호", "종목명 → ISIN코드" 연결이 성공했는지 요약하고, 원본 응답은 `data/raw/probe/`에 저장합니다. (git에는 올라가지 않음)

### 실행 방법

1. 공공데이터포털(data.go.kr)에서 위 5개 API를 활용신청하고 인증키를 받습니다.
2. `.env.example`을 복사해 `.env`를 만들고 `DATA_GO_KR_KEY=` 뒤에 인증키를 넣습니다. (`.env`는 git에 올라가지 않음. 포털의 Encoding 키·Decoding 키 어느 쪽을 넣어도 됩니다.)
3. Node.js 18 이상에서 실행합니다. 설치할 패키지는 없습니다.

```bash
node collector/probe.mjs 삼성전자
```

화면에 인증키는 출력되지 않으므로 결과를 그대로 복사해 공유해도 됩니다.

### GitHub Actions로 점검 (수동 실행)

저장소의 **Actions → probe → Run workflow**에서 종목명을 넣고 실행하면 GitHub 서버에서 같은 점검을 합니다. 저장소 설정(Settings → Secrets and variables → Actions)에 `DATA_GO_KR_KEY` 시크릿을 먼저 등록해 두어야 합니다. 로컬 PC나 회사망에서 API가 막힐 때 "API 자체가 되는지"를 확인하는 용도입니다.

## 폴더 구조

```

├── collector/probe.mjs        # 공공데이터 API 점검 스크립트
├── docs/api-notes.md          # API 규격 메모: 주소, 조회 키, 응답 항목, 운영 규칙, 이용허락
├── .github/workflows/probe.yml# 수동 실행 점검 워크플로

```

## 알아둘 점 (docs/api-notes.md 요약)

- 시세·종목 연결표 API가 **공공누리 4유형(상업적 이용 금지, 변경 금지)**입니다. 지금 조건으로는 비상업적 이용만 가능하므로, 유료 서비스로 만들려면 제공기관 확인이 먼저 필요합니다.
- 데이터는 실시간이 아니라 영업일 하루 뒤 오후 1시 이후에 갱신됩니다.
- 서비스마다 주소에 `/service`가 있는 것과 없는 것이 섞여 있습니다. (스크립트에 반영되어 있음)

### 확인한 것과 못한 것

- 확인함: 가짜 API 응답으로 5단계 호출 흐름, 연결표(crno·ISIN) 추출, 재무 연도 거꾸로 시도, 시세 기간 출력을 실행해 정상 동작하는 것과, 인증키가 화면과 저장 파일에 남지 않는 것을 확인했습니다.
- **확인하지 못함:** 이 작업 환경에서는 data.go.kr에 접속할 수 없고 인증키도 없어, 실제 API 응답으로는 실행하지 못했습니다.
